# ROADMAP

Видение: проект вырастает в три части, каждая из которых
живёт отдельно.

## Проекты

### 1. OmniMark (`.omk`)

Язык разметки: синтаксис в стиле MarkNext (отступные блоки,
структурные ключевые слова) плюс некоторые возможности HTML
(атрибуты, сущности). Детали синтаксиса — TBD.

- Файлы: `.omk`.
- Парсер отдаёт тот же IR документа (`Block`/`Run`), что и
  HTML-конвертация: конвертеры взаимозаменяемы.

### 2. RFONT

Максимально гибкий проект для работы с растровыми шрифтами:

- загрузка bitmap-шрифтов (WOFF/FFTM) и таблиц `.kern`
  (метрики, spacing, couples);
- ячейки глифов, advance, смещения, кернинг;
- рендер ячеек в цвет на произвольный framebuffer.

В составе RFONT не должно быть ни браузера, ни y2pi:
выравнивание, источник файлов и framebuffer — параметры,
не зависимости.

### 3. y2pi (ядро)

Переклассифицируется в **замену DOM**: webview без браузера —
канвас, целочисленный масштаб, скролл, раскладка, выделение,
ввод, документ.

- Нативная поддержка в браузерах: страница подключает один
  файл (текущий режим `boot.js`).
- Поддержка через динамическую конвертацию с помощью аддонов:
  разметка (HTML / `.omk`) конвертируется в IR на лету.
- Внутри y2pi: RFONT (как шрифтовой движок) и `.omk`
  (OmniMark — язык документов).

## Архитектура (сейчас, proof-of-concept)

```
разметка (HTML) ──Scene (scene/dom.js)──▶ IR: Block / Run
                                                  │
RFONT (font/font.js) — ячейки в цвет              ▼
Viewport, Selection, Input, Scheduler  ──Renderer (frame/render.js)──▶ кадр
```

Швы:

- **разметка → IR**: конвейер конвертации в Scene
  (`_walkKids` → отрезки → блоки). Сюда подключаются и
  HTML-аддон, и парсер `.omk`.
- **IR → кадр**: Renderer — единственный потребитель IR.
- **RFONT → пиксели**: `rfont.drawCells(ctx, x, y, cells, color)`.

IR документа (`Block`, `Run` — typedef'ы в `frame/render.js`)
— контракт между конвертерами и Renderer; зафиксировать и
именовать (этап 2).

## Порядок работ

### Этап 1 — RFONT standalone

- `align` (режим PIX_MODE) — функция-параметр, а не
  зависимость от Viewport.
- Источник файлов (woff/.kern) — injectable: браузер —
  `fetch`, node — `fs`, дальше — что угодно.
- Framebuffer запекания спрайтов — injectable: canvas 2d /
  WebGL / программный.
- Свой конфиг (CELL_W/H, ALPHA_CUT, fallback, имя шрифта)
  вне общего `G`.

### Этап 2 — слой конвертации

- Вынести из Scene интерфейс «разметка → IR»:
  конвертер = `{ name, parse(root) → blocks[] }`.
- HTML становится первым конвертером (аддоном).
- Именование и фиксация IR (Block/Run) как контракта.

### Этап 3 — OmniMark

- Спецификация синтаксиса: MarkNext-ядро + HTML-подмножество.
- Парсер `.omk` → IR.
- Интеграция: y2pi открывает `.omk`-документы.

### Этап 4 — y2pi как замена DOM

- Нативный режим в браузерах: что ещё нужно webview без
  DOM (события, формы, навигация — TBD).
- Аддоны-конвертеры как отдельные пакеты (HTML / `.omk` / …).

## Известные проблемы

- `About` описывает POC как есть (Markdown/WebGL/анимации);
  после утверждения роадмапа переводится на новое видение.
- VM-обёртка не реализована (осознанно): RFONT standalone
  (этап 1) снимает её необходимость — RFONT будет ходить
  в node напрямую.
